Isolated Fault-Tolerance Simulation Environment

SANDBOXED DEMO PROCESS ONLY

All failure actions listed below communicate exclusively with the isolated demo subprocess via atomic command files. No arbitrary host processes, system files, or host operating system stability are impacted.

Scenario 01: Process Crash

CRITICAL

Sends an immediate abort signal (os._exit(7)) to the demo subprocess. The process ceases execution abruptly.

Expected Behavior: Failure detector notices PID disappearance, triggers rollback to latest valid checkpoint, and respawns the worker.

Scenario 02: Process Hang (Unresponsive)

HIGH

Signals the demo process to stop updating its internal heartbeat timestamp while maintaining its active PID.

Expected Behavior: Supervisor monitors elapsed heartbeat time. When it exceeds threshold (6.0s), hang is classified and supervisor executes recovery.

Scenario 03: State Corruption

CRITICAL

Injects invalid schemas and bad hash data into the atomic state file (counter: "CORRUPTED").

Expected Behavior: Failure detector performs Pydantic schema validation, detects corrupt types, rejects state, and initiates checkpoint restore.

Scenario 04: Controlled Memory Pressure

MEDIUM

Allocates buffer bytearrays in the worker's memory up to safe demo limits (configurable 40 - 120 MB).

Expected Behavior: Demonstrates RSS memory growth monitoring and resource threshold tracking via psutil.
